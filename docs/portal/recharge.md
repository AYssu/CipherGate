# Portal 充值

**入口：** `/portal/recharge` · **适用对象：** 已登录的应用终端用户

充值页展示当前应用启用的会员方案，包括方案名称、价格、有效天数或永久类型。方案由应用方维护，与平台余额页的配额商品分别管理。

## 购买流程

1. 选择一个会员方案，点击「购买」。
2. 在确认窗口核对订单号、方案名称和金额。
3. 点击「去支付」，进入支付渠道页面完成付款。
4. 返回 [订单记录](/portal/order) 和 [会员信息](/portal/membership)，核对到账结果。

没有支付跳转地址时，页面会提示前往订单记录查看。支付渠道页面显示成功后，仍应确认平台订单和会员状态。

## 结果处理

| 状态 | 下一步 |
| --- | --- |
| 订单已支付，会员已更新 | 本次购买完成 |
| 已付款，平台状态尚未更新 | 稍后刷新；持续异常时向应用方提供订单号和支付凭证 |
| 订单仍待支付 | 核对是否实际付款，避免重复下单付款 |
| 暂无可购买方案 | 联系应用方确认方案是否已启用 |

创建订单还需应用开放 Portal 支付，并启用该应用的支付网关配置；支付回调地址也需与实际部署地址一致。Portal 当前提供购买和订单查询；退款或发票需求请联系应用方处理。

## 加载失败与重复操作

购买方案加载失败时，页面显示「重新加载」；只有成功获取到空列表时才显示「暂无可购买方案」。请求创建订单或支付确认窗口打开期间，其他购买按钮暂时禁用。

「稍后支付」只关闭确认窗口，已经创建的待支付订单仍保留。超时或断网后，先通过「查看订单记录」核对是否已创建订单，再决定是否重试。

## 原价、优惠与限量

应用方在后台「应用管理 → 价格方案」配置现价、可选原价与剩余可售份数，价格输入单位为元。

- 实际订单仅按现价收款。原价高于现价时，购买页显示划线原价与「优惠价」标签；清空原价即可取消展示。
- 库存留空表示不限量；填写 0 表示售罄。有限库存按应用内的具体方案独立计算，修改一个应用不会改变其他应用的方案。
- 「剩余可售」不包含已售出或已被待支付订单占用的份数。编辑时设置的是当前可售余量，不是累计销售上限。
- 下单成功即占用一份，支付确认后消费这份库存。重复回调不会重复扣库存或延长会员。方案价格和天数的后续变更不修改已有订单快照。
- 订单超过 30 分钟后，由每 5 分钟运行的任务通过 SK 网关 `/pay/query` 核对状态；只有确认关闭、失败或退款后才释放预占库存。已付款但回调遗漏时，会补记支付与会员权益。
- 网关超时、不可达、订单不存在或返回不明确状态时，保留订单和预占库存，避免超卖。请应用方先核对网关订单，不要反复下单或直接修改库存记录。恢复网关配置后会继续核对；无法核实的订单需人工处理。

后台编辑期间若发生下单、补货或其他修改，保存会提示刷新后重试，避免旧表单覆盖新库存。存在预占库存的方案可停用，但不能删除或切换为不限量，需先完成待支付订单核对。

## 升级说明

Flyway `V5__portal_plan_discount_and_stock.sql` 只增加字段与约束，不批量修改任何应用的套餐数据。旧方案的原价和库存默认为空，继续按原价格不限量销售；历史订单不占用新库存。要调整价格或开启限量，请在后台按应用分别设置。

回退前应停止新下单、备份并核对所有有限库存订单。旧版本不校验库存，不能直接回退旧 JAR 后继续销售限量方案；应先停用这些方案。不要删除迁移记录或修改已应用的迁移文件。
