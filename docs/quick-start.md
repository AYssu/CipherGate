# 使用指南

CipherGate 的平台账号与应用用户账号分别管理。首次使用先确认账号所属范围，再选择对应入口。

## 选择使用路径

| 角色 | 从哪里开始 | 主要任务 |
| --- | --- | --- |
| 部署维护者 | [部署运维指南](/operations) | 安装平台、配置域名、更新、备份和恢复 |
| 应用所有者或开发者 | [开发者中心](/developer/) | 创建应用、管理授权数据、接入客户端 |
| 平台用户 | [用户中心](/user/) | 查看平台会员、余额、签到、邀请、订单和工单 |
| 应用终端用户 | [应用用户 Portal](/portal/) | 登录指定应用，查看会员、充值、订单和账号设置 |
| 系统管理员 | [管理后台](/admin/) | 管理平台用户、角色、接口权限和系统配置 |

> **账号范围**：应用终端用户的邮箱账号不能用于登录管理后台。平台用户中心的会员和余额，也不会自动变成某个应用内的会员或余额。

## 首次部署平台

在包含安装脚本的发布包中执行：

```bash
python3 install.py
```

脚本生成私有配置并启动服务。默认仅能从本机访问 `http://127.0.0.1:5173`；正式域名安装、远程访问方式和环境要求见[部署运维指南](/operations)。

打开首页后，配置自己的 GitHub OAuth App，并先完成部署者的首次登录。首位 GitHub 登录用户获得超级管理员角色。服务器启动成功与账号初始化是两个步骤，初始化完成后才开放站点。

## 接入一个应用

1. 使用有应用管理权限的平台账号登录后台。
2. 在「应用管理」创建应用，确认应用 ID、App Key 与 App Secret 的用途。
3. 在「卡密管理」或「终端用户管理」准备授权数据。
4. 按业务需要配置变量、加密插件、更新包或第三方充值凭证。
5. 根据 [API 对接指南](/developer/api-integration) 联调请求、签名及错误处理。

创建应用不会自动生成第三方充值凭证。应用的 App Key/App Secret 与充值 API Key/API Secret 分别管理，详见[第三方凭证](/developer/credential)。

## 已有平台上的账号使用

- 平台登录与权限：[首次登录](/quick-start/login)。
- 应用用户注册：[账号注册](/quick-start/register)。
- 账号对应多个应用：[Portal 登录流程](/portal/)。
- 跨应用复制或移动用户：[用户迁移](/developer/user-transfer)。

## 维护已部署的平台

在现有安装目录执行完整更新：

```bash
python3 update.py /path/to/ciphergate-deploy.zip
```

完整更新覆盖后端、前端、文档、官方插件和运维工具，保留原配置、镜像和数据卷。更新流程、旧安装接入和回退条件见[部署运维指南](/operations)。

本文中的平台更新与[应用管理](/developer/application)中的「上传更新包」用途不同：前者更新 CipherGate 本身，后者向你的应用客户端分发安装包。

## 核对文档与运行版本

站点文档位于 `/docs/`，与发布包一起交付。排查前先确认前后端来自同一版本；完整更新会自动执行版本检查。接口实际可用性还受应用状态、账号权限和平台配置影响。
