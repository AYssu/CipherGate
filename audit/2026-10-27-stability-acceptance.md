# 稳定性与体验优化记录

日期：2026-10-27。基线：`a8ac5f34b8c6ba073a594fd0193b4c346fac25d3`（v1.1.5）。分支：`feat/stability-acceptance`。

## 交付范围

本轮完善现有业务闭环、故障定位和恢复证据。没有新增数据库迁移、变更签名协议或修改线上配置。合并、发布和部署仍需分别授权。

| 问题或缺口 | 最终行为 | 验收证据 |
| --- | --- | --- |
| 请求编号仅在服务端，用户难以提供故障线索 | 管理端和 Portal 从响应头提取受限长度、字符的编号，业务失败与 HTTP 失败均展示；保留原始 Axios 错误载荷供文件下载等流程使用 | 前端单元测试、注册拒绝及上传拒绝浏览器测试 |
| 超时、断网、限流、服务故障提示混淆 | 区分错误类型；保留安全的 4xx 说明，5xx 不展示内部细节；未知写入结果提示先查询状态 | `api-response.test.mjs` |
| 上传错误只弹短暂提示，旧包状态不清楚 | 保留持久错误和请求编号，旧文件下载入口保留；上传及保存完成前禁止关闭、切换或提交编辑，避免旧请求污染其他应用 | 桌面与移动端上传拒绝、挂起、下载回归 |
| 方案获取失败伪装成没有方案 | 错误、重试、真正空列表分别展示 | 桌面与移动端浏览器测试 |
| 购买其他方案可能并发创建订单 | 同步 ref 保护，创建请求及确认窗口期间禁用所有购买按钮；说明稍后支付仍保留待支付订单 | 桌面与移动端挂起请求测试 |
| 订单无法正常翻页、失败后无反馈 | 复用已有 List 接口，20 条一页前后翻页；失败时保留旧页并标注，重试原目标页 | 桌面与移动端失败与重试测试 |
| 同秒订单跨页排序不稳定 | 增加 ID 倒序作为固定次级排序 | 25 条相同时间订单真实 HTTP 测试，修复前失败、修复后通过 |
| 回跳参数被当成支付成功证据 | 仅提示已返回，支付结果以服务端订单状态为准 | 伪造 `trade_status=TRADE_SUCCESS` 浏览器测试 |
| 多个服务的测试没有连成真实业务流程 | 真正通过 HTTP、安全链、MySQL 和 Redis 串联注册、登录、签名试用、查询、卡密充值；拒绝路径不重复入账 | 新增 5 项 HTTP 集成测试，含下载与分页 |
| 恢复只验证 SQL，未验证上传文件 | S3 复制至独立主机目录，删除源对象，恢复 SQL 和新桶，实际下载并核对长度、摘要和数据库引用 | 真实 MySQL 8.4 + 发布同镜像 S3 对象恢复演练；12 项工具回归 |
| 验收证据分散 | 文档固定矩阵、命令和人工边界；CI 保存带构建信息、阶段和结果的恢复 JSON | `docs/stability-acceptance.md`、工作流附件 |

## 本地验证

- 后端：341 项单元测试、96 项集成测试，失败 0、跳过 0；覆盖率报告及 JAR 构建通过。集成测试使用专用 MySQL 8.4、Redis；HTTP 流程只替代邮件发送和外部对象存储适配器，不替代认证、签名、事务或数据访问。
- 前端：lint、26 项单元测试、类型检查和生产构建通过；74 项桌面与移动浏览器测试通过，检查注册、验证码、卡密、更新包、订单、失败恢复和 320px 布局。
- 工具：76 项部署脚本测试、8 项 CI 脚本测试通过。
- 恢复：独立临时 Compose 环境验证 3 个对象（二进制、嵌套空格名称、空文件），共 3838 字节；下载摘要、数据库引用和目标保护通过，用时 13.346 秒；资源已清理。
- 文档：构建通过。前端和运维变更经独立代理复核，未发现阻断问题。

完整打包生命周期和 MySQL 8.0 验证由本分支 PR CI 提供，以当前提交的检查结果为准，不预先将待运行的 CI 记为通过。

## 验证边界与后续

浏览器测试模拟 API；真实后端集成及 S3 恢复测试另行证明安全链和数据处理。QQ User-Agent 测试不等同于实机 QQ 内核兼容性认证，邮件发送和真实支付仍需专用账号、渠道沙箱或单独授权验证。演练不证明某份生产备份已可恢复。

性能方面，公开页已有路由拆分及防止加载管理编辑器的回归；构建仍提示少数管理端编辑器块较大。后续依据访问和体积数据处理，不在本轮改动编辑器或插件架构。插件进程隔离、孤立对象清理重试和多节点缓存一致性作为独立工作保留。
