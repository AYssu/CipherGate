# Portal 密码找回

密码找回入口为 `/portal/recovery`，用于重置指定应用中的终端用户密码。

## 操作步骤

1. 输入注册邮箱与图形验证码并申请发送邮件。为防止账号枚举，页面不会确认邮箱是否已注册。
2. 填写收到的邮箱验证码，点击“验证邮箱”。验证通过后才会显示关联应用。
3. 图形验证码只能使用一次；错误或发送失败时重新获取。
4. 选择要重置密码的应用。
5. 输入6–50位的新密码（UTF-8编码不超过72字节）并提交。

## 注意事项

- 重置按应用进行，同一邮箱在不同应用中的密码可能不同。
- 验证码 5 分钟内有效。收不到时检查邮箱地址和垃圾邮件；第二步可选择“更换邮箱或重新获取验证码”返回第一步。
- 未注册邮箱不会收到找回邮件，也不会暴露关联应用。验证码尝试、来源、收件地址和全站发信均有限额；超过限额请稍后重试。
- 重置成功会撤销该应用用户已有的门户会话，需要重新登录。
- 平台账号不能通过 Portal 找回，可通过 GitHub 登录后修改平台密码，或联系系统管理员。

## 接口与升级兼容

- `POST /api/portal/auth/recovery/send-code` 接收 `email`、`captchaId`、`captchaCode`；图形挑战来自 `GET /api/portal/auth/captcha`。
- 关联应用改为 `POST /api/portal/auth/recovery/apps`，请求体必须包含 `email`、`verifyCode`。验证码不放在URL中，旧的匿名GET入口不再提供应用列表。
- 设置页发送换邮箱验证码要求正式登录，挑战绑定当前用户、应用和目标邮箱；临时选应用票据没有设置、订单、支付权限。
- 本次升级启用独立会话用途与凭据指纹，已有门户令牌需要重新登录。多应用票据最多有效5分钟，只允许进入本次已分别验证密码的应用。
- V3迁移仅扩大验证码用途和邮箱列长度，不改变已有业务数据。回退应用代码不能恢复已消费验证码或已修改密码；数据库恢复遵循部署备份流程。

找回发信采用有界后台队列，已注册与未注册邮箱都先进入相同队列，HTTP响应不会等待SMTP或查询账号。队列满时统一提示服务繁忙。该队列不是持久消息存储；服务重启或邮件提供商失败时，可在60秒冷却后重新申请验证码。
