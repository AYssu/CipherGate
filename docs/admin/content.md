# 内容与运营

内容模块包括平台公告、站内文档、管理端订单和工单。

## 公告

公告包含标题、内容和状态。启用的公告可展示给目标用户。公告与某个应用的客户端公告不是同一份数据，应用公告在应用管理中维护。

## 文档管理

文档按分类组织，文档项包含标题、正文、作者信息、排序、状态和附件。管理员可以：

- 新增、编辑和删除分类。
- 新增、查看、编辑和删除文档。
- 管理附件并记录下载次数。
- 通过 `/admin/docs/view/:id` 查看文档。

文档正文使用站内文档能力发布；VitePress `/docs/` 是本仓库维护的产品使用文档，两者用途不同。

## 管理工单

管理员可以按待处理、处理中、等待回复、已解决和已关闭筛选工单，查看对话、回复、催办和关闭。

处理支付、权限和第三方调用问题时，优先使用订单号、用户 ID、应用 ID、请求 IP 和 traceId 关联日志。

## 管理端订单

管理端订单页用于跨用户核对订单和手动发放。手动发放不是退款功能，也不能替代支付渠道的原始支付凭证。

## 文档附件分片上传

`/api/upload` 仅用于管理端文档附件，应用更新包和插件使用各自的专用接口。每次请求需要当前管理账号具备 `FILE_UPLOAD` 和 `DOC_ITEM_CREATE` 权限，并验证目标文档存在。上传、查询、合并、取消均限定为初始化的创建人。初始化请求的 `objectKey` 应为 `doc-attachments/{文档ID}/{文件名}`，后端会生成唯一对象键，客户端保存附件时必须使用响应中的 `objectKey`。

文件最大 512MB，默认分片 5MB，单片最大 16MB，最多 4096 片；所有声明值必须为正数。实际读取字节数必须匹配预期，相同编号相同内容重试不会重复计数，不同内容会被拒绝。每账号最多 4 个会话、声明总量最多 1GB；单进程最多 64 个会话、声明总量最多 2GB。单个账号不能占满全局预留额度，完成、取消或过期会释放预留。

分片请求的浏览器超时为 5 分钟，完成请求为 30 分钟；完成阶段需要磁盘合并并写入 MinIO。随包 Nginx 为 `/api/upload/chunk` 和 `/api/upload/complete` 分别设置 5 分钟和 30 分钟超时，普通 API 继续使用原预算。额外 CDN/WAF/反向代理也需要允许对应超时，否则仍可能发生网关超时。更新工具会保留现有生产 Nginx 配置，因此旧部署升级后需要运营者单独同步这两个端点的配置，不能仅靠前端超时生效。

暂存文件写入本地磁盘，合并使用 8KB 复制缓冲区；MinIO SDK 另有有限的分段缓冲，避免将整个更新包读入堆。合并时磁盘占用最多约为暂存总量两倍，需预留足够空间。

暂存目录通过 `app.upload.staging-directory` 配置，默认 `${java.io.tmpdir}/ciphergate-upload-staging`。该目录须由单个后端进程独占，禁止共用或放置业务文件。**当前会话不支持跨重启或多副本续传**，重启后需重新上传；启动时回收专用目录内符合 UUID 规则的旧会话目录，不删除 MinIO 业务对象。每 10 分钟清理超过 24 小时的会话，完成和取消也会清理全部实际分片。MinIO 上传失败会保留分片以便重试完成，合并临时文件会删除。

本次升级无需数据库迁移。已完成的附件和应用更新包保持可用，进行中的旧会话需重传。旧版本遗留的 MinIO `.chunk.N` 对象不自动清理，应核对归属及业务引用后另行处理。
