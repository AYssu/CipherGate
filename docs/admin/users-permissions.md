# 用户与权限

平台权限由用户、角色、菜单和 API 权限四部分组成。

## 用户管理

平台账号通过 GitHub 首次授权登录创建。管理员可以维护已有用户、启用/停用账号、分配角色；超级管理员可重置平台密码。用户可同时拥有多个角色，最终菜单和 API 权限取授权结果的并集。

重置密码需要已登录、拥有用户更新 API 权限，并通过超级管理员角色校验。若返回 `401 未登录`，先重新登录；提示权限不足时同时核对 API 权限和超级管理员角色。

## 角色管理

角色包含角色名称、编码和描述。管理员为角色分配：

- 菜单权限：控制后台导航和页面入口。
- API 权限：控制后端资源接口。

仅分配菜单会出现“页面可见但接口 403”，因此两者应一起检查。

## 菜单管理

菜单项维护名称、编码、父级、类型、路由、组件、图标、排序、可见性和状态。删除父菜单前先处理子菜单。

## API 权限

权限项包含权限名称、编码、资源类型、资源路径、HTTP 方法和状态。创建权限时必须与后端实际接口匹配，错误的路径或方法会导致角色授权无效。

## 推荐授权流程

1. 创建角色并分配菜单。
2. 添加该角色实际需要的 API 权限。
3. 给测试账号分配角色。
4. 分别验证页面可见性、查询、保存、删除和重置密码。
